Git не фиксирует каждое изменение автоматически. Вместо этого вы явно выбираете, какие изменения попадут в следующий снимок. Этот двухэтапный рабочий процесс строится вокруг **области подготовленных файлов (staging area)**.

Представьте это как буфер обмена для следующего коммита. Файл проходит через три состояния:

1. **Рабочий каталог**: где вы обычно редактируете файлы.
2. **Область подготовленных файлов**: изменения, которые вы пометили для следующего коммита.
3. **Репозиторий**: постоянная история после выполнения коммита.

Смысл индексации (staging) заключается в контроле. Вы можете отредактировать десять файлов, но добавить в индекс только два, относящихся к исправлению одной ошибки, закоммитить их, а затем проиндексировать и закоммитить остальные отдельно. В результате каждый коммит будет сфокусирован на одном логическом изменении.

Вы перемещаете файлы в область подготовленных файлов (staging) с помощью `git add`, а из области подготовленных файлов в репозиторий — с помощью `git commit`.
