Если обе ветки развивались независимо, Git не может просто выполнить fast-forward. Вместо этого он выполняет **трехстороннее слияние**: он берет общего предка и верхушки двух веток и создает новый коммит, который их объединяет.

Этот новый коммит является **коммитом слияния (merge commit)**. У него два родителя, по одному из каждой ветки:

```bash
git switch maingit merge feature -m "Merge feature"
```

Флаг `-m` позволяет указать сообщение коммита слияния напрямую, поэтому Git не открывает редактор.

В большинстве случаев Git может автоматически объединять изменения из обеих веток, если они затрагивают разные части файлов. Конфликты возникают только тогда, когда в обеих ветках изменены одни и те же строки, и это тема следующего урока.
