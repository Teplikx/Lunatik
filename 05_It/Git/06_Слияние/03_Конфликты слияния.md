Если обе ветки изменили **одни и те же строки** одного и того же файла, Git не может угадать, какую версию оставить. Он приостанавливает слияние и просит вас принять решение.

Конфликтный файл получает специальные маркеры, показывающие обе версии:

```diff
<<<<<<< HEADthe version on main=======the version on feature>>>>>>> feature
```

Ваша задача — отредактировать файл вручную: выберите одну версию, объедините их или напишите что-то новое. Затем удалите все маркеры конфликтов (строки `<<<`, `===`, `>>>`).

Как только файл будет выглядеть правильно, добавьте его в индекс и завершите слияние еще одним коммитом:

```bash
git add notes.txtgit commit -m "Resolve merge conflict in notes"
```

Если вы передумаете на полпути, вы можете прервать весь процесс и вернуться к состоянию до слияния:

```bash
git merge --abort
```
